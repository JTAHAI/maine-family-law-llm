Troubleshooting

If a parser is missing, the file is inventoried as needs-human-review or unsupported, and the build continues with warnings.

Windows setup fixes

Use these checks when the launcher or local workbench does not start on Windows.

PowerShell blocks a script

If PowerShell reports that script execution is disabled, run the project script with a process-scoped bypass instead of changing the machine policy:

powershell -ExecutionPolicy Bypass -File .\START_LOCAL_TEST.ps1 -SkipTests

You can use the same pattern with other project scripts, for example:

powershell -ExecutionPolicy Bypass -File .\START_LOCAL_CHAT.ps1

Python is not found

Open a new terminal after installing Python, then check which launcher is available:

py -3 --version
python --version

If neither command works, reinstall Python and enable the option that adds Python to PATH. If both work, prefer the project launcher scripts because they set the local paths for you.

Virtual environment activation fails

If activating the virtual environment fails, rebuild it from the repository root with the local test script:

powershell -ExecutionPolicy Bypass -File .\START_LOCAL_TEST.ps1 -SkipTests

If you activate it manually, use the repository-local environment path:

.\.venv\Scripts\Activate.ps1

Port 8000 is already in use

The local API normally starts on http://127.0.0.1:8000/. Stop the project server first:

.\STOP_LOCAL_TEST.ps1

If another process is using the port, find it and stop it from an elevated terminal only if you recognize it:

Get-NetTCPConnection -LocalPort 8000 -ErrorAction SilentlyContinue |
  Select-Object LocalAddress, LocalPort, OwningProcess

Launcher closes immediately

Start the launcher from an already-open PowerShell window so the error stays visible:

.\START_MAINE_FAMILY_LAW_LLM.cmd

Then run the local smoke check to verify the source checkout and fixture path:

powershell -ExecutionPolicy Bypass -File .\scripts\run-local-smoke.ps1 -RepoRoot . -DataRoot C:\dev\ME_FM_LLM_data
