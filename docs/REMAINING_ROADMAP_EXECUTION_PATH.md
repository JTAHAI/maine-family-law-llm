# Remaining roadmap execution path

This is the dependency-first path for completing slices 62–200 after source-checkout implementation of 1–22 and 24–61. Slice 23 remains externally blocked: no admitted local cross-encoder model artifact or admission record exists. This is an implementation and evidence plan, not a release certification. A slice is publicly accepted only after its service, protected canonical API, production UI, meaningful fictional action, artifact/source drill-down, visible review state, focused tests, and frozen/package reachability are directly evidenced.

## Operating cadence

1. Implement one coherent vertical slice at a time, preserving existing work.
2. Run its focused service/API/UI tests, route-collision check, Python compilation, and production-bundle syntax check.
3. Record source-checkout proof in `dist/ga_today/evidence/` and disclose browser, frozen-executable, package, or external-evidence gaps.
4. At each wave boundary, run the cross-slice regression set and repair regressions before beginning the next wave.
5. Run a final whole-product E2E and package qualification only after all internally testable slices are complete.

## Acceptance gates by class

- **Public authority (36–40):** Must preserve official-source identity and hashes, never silently replace a source, and distinguish metadata from legal conclusions.
- **Private matter data (41–100, 151–154, 171–180):** Must bind to the active matter and tenant, use encrypted durable state where stored, write audit receipts, and show review-required status.
- **Untrusted inputs (51–70, 135–140):** Must quarantine unsafe content before parsing or tool use; all derived artifacts retain original provenance.
- **User-interface work (101–130):** Must pass keyboard, focus, semantic, overflow/zoom, loading/error/empty-state, and production-asset checks.
- **Release work (155–160, 196–200):** Must be tested on the exact candidate package. Source-checkout tests alone cannot certify MSIX, Store, or Enterprise readiness.

## Certification boundary

The engineering campaign can fully implement and test internal controls. The following cannot be truthfully self-certified from synthetic or source-checkout tests: live official-authority currency, attorney-reviewed gold data, controlled attorney sandbox use, controlled pilot results, approved signing, WACK execution where required, organizational sign-offs, or Microsoft Store/Enterprise GA approval. The roadmap will create the required evidence paths and fail-closed release gates; each of those external prerequisites remains blocked until real evidence is supplied.
